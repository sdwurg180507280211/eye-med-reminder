# eye-med-reminder

眼科用药提醒助手 Flutter 应用，支持 Android / iOS。当前版本 **0.2.0+2**：以蓝白色卡片、清晰文字和小狗陪伴为基础，提供本地患者档案、处方核对、今日提醒、实际用药记录及已保存计划管理。iOS 与 Android 桌面图标采用同一小狗形象。

## 运行

使用 **Flutter 3.47.6 stable / Dart 3.13.5**。Android 项目需要 JDK 17、Android SDK（compileSdk 由 Flutter 指定，至少35）及相应 NDK；iOS 需要 macOS、Xcode、CocoaPods（不支持 Swift Package Manager 的插件由 Flutter 使用 CocoaPods 集成），最低 iOS 15。

## 使用流程

首次使用创建姓名和6位数字密码的患者档案，之后输入相同姓名和密码登录。登录页支持显示/隐藏密码、键盘下一项/完成和提交期间的防重复操作；每个档案的计划与用药记录相互独立。

底部有三个入口：

- **今日**：下一次提醒、今日用药时间线、由本人确认的用药进度、后续复查及系统提醒状态。尚未到点的剂次不能提前记录；时间经过只显示“待记录”，不会自动判断已用药或漏用。
- **用药计划**：核对待确认草稿，或查看已保存计划、疗程、原始提醒时间、处方照片和历史用药记录。已保存计划可以暂停、恢复整份计划的用药与复查提醒。
- **添加处方**：拍摄或选择处方照片，然后对照照片手动录入药物；也可直接手动录入。照片支持替换和移除，草稿可以经确认后清空。

药物录入按“药物信息 / 疗程与频次 / 提醒时间”分组，必须填写药品名称、用药眼别、每次剂量、频次、疗程开始日期和天数。眼别错误在选项附近显示，提醒时间实时显示已选数量及频次要求；修改药物显示“保存修改”，未保存退出前可以选择继续编辑或放弃修改。页面支持窄屏、大字号和滚动，常用操作按钮保持足够的点击面积。

确认计划前可修改、删除药物并调整顺序，设置复查日期及提前3/2/1天提醒。确认后计划独立保存；再次添加处方不会覆盖已有记录。

后台点击系统通知进入对应提醒；应用在前台时，到点进入提醒页面。提醒显示患者姓名、药品、眼别、剂量与时间，并使用系统中文语音播报。可以停止或重新播放语音；语音失败或超时保留文字和静态小狗，系统开启减少动态效果时小狗不播放嘴部动画。

**“结束提醒”只关闭页面。** 实际用药后可单独点击“我已按医嘱用药”，或在“今日”点击“记录已用药”并确认。记录会持久保存，也可在“今日”撤销；详情中可查看每种药物的历史剂次及记录时间。记录使用原始剂次身份，其他计划引起的时间错开不会改变已记录状态；保存失败会回滚并提供重试反馈。

**“暂停提醒”只暂停通知，不代表停药建议。** 处方、照片与用药记录仍保留，是否继续用药需按医生指导决定。恢复时会按当前疗程重新安排后续提醒；如与其他未暂停计划存在同名药物、重叠疗程、重叠眼别及同时间的重复项，将阻止恢复并提示核对。

## 数据与提醒

- 姓名 + 6位数字密码创建/登录；同名患者可用各自密码区分。密码使用 PBKDF2-HMAC-SHA256、随机盐和100000次迭代，不以明文保存。
- 档案、确认计划、暂停状态和实际用药记录写入 Android Keystore / iOS Keychain 支持的安全存储；兼容原有 `patients_v1` 档案及历史通知 payload。退出保留已保存记录并取消当前档案通知，再次登录后恢复未暂停计划的排期；应用重启需要登录。
- 处方照片复制到应用私有目录，确认后的照片可在详情查看。替换、移除照片或清空草稿会清理未被已保存计划引用的照片；照片不上传，照片文件本身未单独加密。照片权限失败时可继续手动录入。
- 不默认选中药物、剂量、眼别、频次、疗程或提醒时间。08:00 / 12:00 / 17:00 仅为可选时间，支持自定义时间；数量必须匹配频次。“每N小时1次”校验24小时循环，包括跨夜间隔。
- 同原始时间、同一天处于疗程内的多种药物，按确认顺序依次错开10分钟；不同处方也参与排序，旧处方在前。跨午夜保留实际次日日期；疗程结束后不再安排该药物提醒。确认时拦截重叠疗程、同名药物、重叠眼别和同时间的重复项。
- 保存前核对实际提醒时间的重合，包括前一天错开到午夜后的剂次；提示后保留用户核对的时间，不自行改动医嘱。下一次提醒按实际时间排序，跨午夜剂次不会遮住更早的次日提醒。
- 详情展示每种药物的原始提醒时间和历史记录；当天实际错开时间以“今日”时间线为准。
- 复查可设置提前3/2/1天多选，所选日期08:00提醒；不选择提前天数则不安排提前提醒。
- 登录及点击“重新检查”可以申请通知权限。回到前台时仅检查并补排，不主动弹出权限请求；每次重排重新读取当前设备时区，使用设备本地时钟。
- 系统提醒状态显示通知可用性、已安排数量和排期截止日期；授权或调整设置后可点击“重新检查”更新。Android 未允许精确闹钟时会降为非精确通知，并提示可能延迟。
- 为兼容 iOS 64条待办通知限制，仅安排最近 **60条**（含复查），已确认用药的剂次不再重复提醒。登录、确认计划、记录/撤销、暂停/恢复及回到前台会更新排期；需在显示的截止日期前再次打开应用补排。

## 当前边界

- 不模拟 OCR，不注入示例药物，不依据常规用法自动补齐医嘱。照片当前用于人工核对，疗程开始日期需按处方填写。
- `DrugCatalog.lookup(exactName)` 保留资料库查询接口，但当前未接入真实药品资料库。查询时明确提示无资料，不模拟说明书，也不据此推断剂量。
- 已保存计划支持详情、历史记录和提醒暂停/恢复；直接修改已确认处方中的药品、剂量或疗程仍需后续明确的变更流程。新增计划前请核对重复用药，调整医嘱需咨询医生。
- 草稿仅保留当前会话，确认后才持久化；退出档案会清空未确认草稿，并提供确认提示。
- 后台或应用关闭时使用系统通知，不能保证自动弹出全屏小狗或后台动态语音；点击真实通知后才进入页面并播报。没有“测试用药提醒页面”入口。
- 前台恢复仅补弹最近5分钟内的到点提醒，避免大量过期提醒一起出现。系统时间或时区变化后需回到前台重排；历史通知可以点击查看，已暂停或已记录的剂次会提示查看“今日”状态。
- 无限期不打开应用的长疗程自动续排尚未实现。系统通知权限、静音、勿扰、厂商省电或强制停止会影响触达，需要真机验证。
- 纯本地档案，不是服务端账号，没有密码找回、云同步或医生后台。更换设备不会自动同步，卸载后的数据恢复不可保证。

## 后续待接入

1. 真实处方 OCR，识别结果必须由患者逐项确认，不自动补齐医嘱。
2. 有来源的药品资料库，实现 `DrugCatalog` 查询。
3. 狗狗动画与嘴型素材、方言 TTS、语音预生成及本地缓存；当前普通话依赖系统中文语音引擎，部分设备需安装离线中文语音包。
4. 长疗程通知续排、平台权限及省电场景的真机可靠性验证，以及正式分发所需的 Android / iOS 签名与发布配置。

## 代码布局

- `lib/main.dart`：今日时间线、计划与草稿管理、历史详情、前台提醒流程。
- `lib/forms.dart`：患者档案登录与药物录入。
- `lib/design_system.dart`、`lib/dog_avatar.dart`：共享蓝白视觉和小狗绘制/动画。
- `lib/models.dart`：档案、计划、稳定剂次身份及时间计算。
- `lib/storage.dart`：本地安全存储、密码校验及失败回滚。
- `lib/notifications.dart`：系统通知、权限检查与设备时区同步。
- `lib/drug_catalog.dart`：药品资料库接口。
- `test/`：时间计算、存储与患者隔离、通知和 UI 回归验证。
- `tool/generate_app_icons.dart`：复用小狗矢量绘制生成 iOS / Android 全尺寸 RGB 图标，无透明通道。运行 `flutter test --no-pub tool/generate_app_icons.dart` 可重新生成。
